ICEBERG · FIREBASE SETUP

Новая структура Айсберга

Подготовка правил и схемы Firestore. Эта страница не содержит Admin SDK и не может самостоятельно публиковать Firebase Security Rules — Firebase разрешает менять их только через консоль/CLI с правами владельца.

Важно перед включением правил

Код приложения должен использовать коллекции iceberg_profiles, iceberg_contacts, iceberg_chats, iceberg_groups, iceberg_channels и iceberg_seda_handshakes. Пока клиентские модули ещё обращаются к старым путям users, messages, groups, channels и seda_handshakes, эти новые правила не являются совместимыми с текущим приложением. Не публикуй их, пока миграция путей в коде не завершена и не проверена.

1. Предлагаемая структура

  • iceberg_profiles/{uid} — только публичная часть профиля.
  • iceberg_contacts/{uid}/items/{contactUid} — контакты владельца.
  • iceberg_chats/{chatId} — личный чат, поля memberUids, createdBy, createdAt.
  • iceberg_chats/{chatId}/messages/{messageId} — сообщения участников.
  • iceberg_groups/{groupId} — группа, поля memberUids, adminUids, ownerId.
  • iceberg_channels/{channelId} — канал, поля memberUids, adminUids, ownerId, isPublic.
  • iceberg_seda_handshakes/{id} — обмен ключами только между initiator и peer.

2. Правила Firestore для новой схемы

Скопируй в Firebase Console → Firestore Database → Rules только после завершения миграции кода и проверки тестами.

3. Порядок запуска

  1. Открой Firebase Console и выбери проект glob-data.
  2. Сначала переведи код на перечисленные пути и добавь проверку членства в чате/группе/канале.
  3. Прогони Firestore Emulator Rules tests для владельца, участника и постороннего пользователя.
  4. Вставь правила в консоль и нажми Publish.
  5. Создавай документы по мере использования приложения; Firestore не требует предварительно создавать пустые коллекции.
